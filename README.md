# LemonCAD

A separate CAD application using React, Three.js, FastAPI, OCP and PostgreSQL.
The first page opens a real STEP/STP/STL; no login needed to measure or export.

## Local development

Requirements: Docker, Node 22+, uv, Python 3.12.

```sh
docker compose -p lemoncad up -d
uv sync --python 3.12
uv run python -m backend.migrate
npm ci --prefix frontend
```

Run these in separate terminals from the repository root:

```sh
uv run uvicorn backend.main:app --host 127.0.0.1 --port 8048
uv run python -m worker.main
npm run dev --prefix frontend
```

Open http://127.0.0.1:5178. Local disk storage is in `.data/objects`; the isolated
Postgres container uses port 55438. No Bixl database or service is touched. The sample
is actual STEP geometry, generated by `uv run python scripts/sample.py`.

## What works

- Anonymous STEP/STP import, exact face-derived distances/angles/radii, STL point
  measurements with explicit source units, PNG/PDF of current view + dimensions.
- Email/password accounts, folders/subfolders, immutable draft revisions, camera
  and annotation restore, explicit publishing, expiring/revocable folder links.
- Email-bound invitation links and membership revocation. Links are copied manually;
  the app does not send emails. Folder viewers see only published revisions.
- Queued OCP draft drawings, material/density inputs, SVG sheet review, reviewed PDF,
  saved drawings included in published project revisions.
- Entitlement-protected costing with explicit rates, calculation downloads and comparison.
- Entitlement-protected fixture briefs; **automatic fixture design is not enabled**.
  The bundled design-fixture workflow still requires engineer-authored geometry/spec,
  a datum review, concept review and explicit delivery authorization. Briefs remain
  `awaiting_engineer`; no production-ready fixture is fabricated by a placeholder.

## Railway deployment configuration

Provision a new project with Postgres, a private Railway S3 bucket, an API service and
one worker service from this repository. This repository has not been deployed.

- API uses root `railway.toml`; worker uses `worker/railway.toml` with repo root build
  context. Both build the root Dockerfile. API serves the built React app and API on
  one origin; the worker has no public domain.
- Set `DATABASE_URL` to the private Postgres connection on both services.
- Set `S3_ENDPOINT`, `S3_BUCKET`, `S3_ACCESS_KEY_ID`, `S3_SECRET_ACCESS_KEY`,
  `S3_REGION=auto` on both. Never expose these to frontend variables.
- API: set `APP_ORIGIN=https://<your-domain>` (no trailing slash), `COOKIE_SECURE=true`.
- API pre-deploy applies numbered schema migrations (currently 001 and 002). Future migrations must be
  numbered; metadata create_all is not an upgrade mechanism.
- Initial worker: one replica, one job at a time, 2 GB memory starting allocation;
  measure actual heavy-part usage before choosing production resources.
- Jobs run in separate Python subprocesses with 180-second deadline, cancellation,
  claim locks and stale leases. Use a private bucket: downloads pass application access
  checks, including revoked links. Anonymous/unsaved files expire after 24 hours;
  the worker removes their bytes hourly. Saved files have no expiry.
- Take managed Postgres backups and separately back up the bucket. Test restores of
  both: database backups alone cannot recover model bytes. Object keys are immutable.

## Verification

```sh
npm run build --prefix frontend
npm test --prefix frontend
uv run pytest
PYTHONPATH=worker uv run pytest worker/tests/test_indexed_map.py
uv run python -m unittest discover -s worker/vendor/draft-drawing/tests
```

New integration tests use a separate PostgreSQL database `lemoncad_test`; they never
truncate the application's database. Test setup instructions are in the test module.

## Launch boundaries

STEP/STP and STL only. Native SolidWorks/Inventor files must be exported to STEP.
STL is an approximate triangle mesh; it cannot yield exact CAD-feature dimensions.
STEP numbers are based on the source model, rounded to 0.001 mm; no manufacturing
accuracy or tolerance certification is implied. Draft drawings report unsupported
features and require review.

Pricing, checkout, account verification/password recovery, abuse protection suitable
for public anonymous uploads, storage quotas, malware/resource sandbox hardening and
an engineer-operated fixture delivery adapter remain launch work. Do not present
this local build as production-hardened. Sessions use HttpOnly cookies and Argon2
passwords; initial account access has no email verification or recovery service.
Manual test entitlements: `uv run python -m scripts.grant EMAIL costing` (or fixture).
Never add private shop rates to the repository. Review reused engine distribution
rights in `worker/PROVENANCE.md` before public release.
